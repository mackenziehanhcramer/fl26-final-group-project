##  Original goal and how much of it was achieved:
### Original goal: 
We wanted to create a music playing radio station based on friends' music and recommendations. We imagined integrating the functionality and design of a car radio with the personality of having a social aspect with your close ones. 

### How much was achieved:
Using Spotify's API, we were able to successfully integrate music and playing directly within our project. Our design does resemble (for the most part) classic analog car radios in set-up and buttons (such as integration of ideas like presets). We were also able to allow usage of friend's playlists directly within the site to allow for music stations to be created and returned to.

##  Project description and functionality:
### Project description:
A user is able to log onto the website and directly input a playlist (taken from Spotify). From there, they can specify the friend's name the playlist is coming from and a station will automatically populate on the screen.

### Functionality:
A user can do a few things such as
- add new stations: inputting new stations from the button on the top right
- play and pause music: around the middle of the page is a button users can press to pause or play a station. This provides a little more benefit than a classic station where you can't pause a song
- save a station through preset: all friends' stations are saved, but if there are specific stations that are particularly enjoyable than you are able to simply press that preset button to make it easier to go back to

##  What was learned, mistakes, challenges, etc.:
### Challenges and Mistakes
We ran into a few unexpected challenges which we had to pivot from.
- limitations from API: while Spotify enabled us many wonderful features, it also limited the availability to actually create or add stations since they were based upon Spotify playlists.
- unnecessary or repetitive features: we intially included both a "preset" and "favorites" section which seemed to end up serving the same purpose. Selection and understanding of actual purpose vs inclusion of more features for less value was a general concern we came across.
- recreating analog/existing design: while we had invisioned starting from a blueprint of an existing design to this new one would be helpful (and it was in some ways), it also made it a little harder to fit more modern and useful functionality within a pre-existing schema. For example, people did not necessarily need to have a volume toggle on the website itself since they would be accessing it from devices which allowed control of that directly.

### Takeaways
This project was pretty fun, but there were some issues that arose that may be slightly unexpected. As a team, we primarily split different files and sections across one another. While helpful logistically, understanding how to fit all these different files with one another (especially to preserve the functionality originally designed and hoped for), was an ongoing challenge we had to navigate.
